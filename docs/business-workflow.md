# GEO/OS 企业业务流程

1. 创建企业工作区、品牌/别名、竞品，配置成员及服务端 API。企业管理不是日常操作的第一屏。
2. 知识：采集/上传证据 → 提取或录入事实草案 → reviewer/owner 审核 → 当前公开事实供优化。内部资料不能发送给公开内容 Agent。
3. 监测：非品牌决策问题 → 手动/授权定时采样 → 按引擎模型保存原始回答。知识准备与监测可并行。
4. 回答复核：分析候选 → 人工确认推荐分类与冲突，区分未审核与已审核指标。
5. 机会洞察：按同问题、同引擎、同模型的描述性差距核查 → 保存优化行动；不将样本差距当因果结论。
6. 官网诊断并行路径：授权静态扫描 → 发现问题 → 整改任务 → 人工实施 → 同 URL 新诊断复核。与内容行动独立。
7. 内容行动：待处理 → 事实关联提纲 → 审批/驳回 → 人工执行 → 新有效样本复盘。渠道文案须从已批准行动建立，独立审批；真实发布登记后可以录入/同步传播数据。优化行动执行状态不会被发布登记自动改变，避免错误地把一条渠道发布视为全部行动完成。
8. 效果：同问题/模型执行前后对比 + 发布日龄渠道快照 + 明确引用/检索来源关联；持续采样。不是因果 ROI。
9. 自动化为辅助分支，默认关闭；授权、额度、暂停和审核边界不变。管理员权限与账单独立。

界面排序不是强制项目状态机；不要求官网诊断才能建立内容行动，也不要求完成事实审核才能监测。事实审核是公开内容生产的必要前置；真实发布与行动执行分别登记。未配置外部 API 不提供虚假样本。
