# GEO/OS — 企业 GEO 优化工作台

GEO/OS 是一个面向企业市场、品牌、公关、内容、产品和数据团队的生成式引擎优化（GEO）工作台。它围绕“监测 → 诊断 → 行动 → 复盘”建立闭环，帮助企业观察品牌在 ChatGPT、DeepSeek、豆包、元宝、Gemini、Perplexity 等 AI 引擎中的可见度，并把内容缺口、事实冲突和信源问题转化为可执行任务。

在线演示：[geo-os-workbench.swift-lake-5238.chatgpt.site](https://geo-os-workbench.swift-lake-5238.chatgpt.site)

> 当前版本为可交互的产品原型，界面数据均为安全的示例数据，尚未连接真实企业数据或第三方 API。

## 核心能力

- **GEO 指挥舱**：综合健康度、AI 声量份额、推荐率、引用率与趋势总览
- **AI 监测**：提示词管理、多引擎筛选、批量采样状态和幽灵引用观察
- **机会洞察**：将内容缺口、信源缺口、事实冲突和技术问题转成行动建议
- **内容作战**：机会入池、事实核验、专家增益、合规审批、分发与引用复盘
- **知识底座**：维护企业唯一事实源、证据覆盖率、新鲜度和公开/内部资产分级
- **风险纠偏**：处理 RAG 污染、旧负面、价格幻觉和品牌实体定义冲突
- **ROI 归因**：统一观察 AI 引荐访问、零点击线索、品牌搜索增量和 CRM 商机

## 产品方法

工作台遵循以下企业 GEO 原则：

1. 用不含品牌词的真实决策问题监测“出现概率”，避免把单次回答当作稳定排名。
2. 内容生产必须由企业事实与原始证据驱动，AI 负责搭骨架，业务专家负责信息增益。
3. 官网、行业媒体、社区问答、评测和百科共同构成 AI 的信源共识。
4. 监测的目的不是生成报表，而是找到下一步可执行的内容、技术、PR 或事实修复动作。
5. GEO 价值不能只按点击归因，需同时观察表单自报、品牌搜索与 CRM 线索。
6. 自动化可以采集、分析和写草稿，但外部发布与事实声明必须经过人工审批。

## 真实监测服务（阶段一 MVP）

原在线演示保留。新增独立本地服务，不依赖 D1 或前端构建。Node.js >=22.13.0，内置 SQLite（可能显示实验性警告）。

```bash
# 从安全终端环境注入供应商密钥，不要提交到 Git
# DeepSeek: DEEPSEEK_API_KEY + GEO_DEEPSEEK_MODEL（账户可用模型 ID）
# Perplexity: PERPLEXITY_API_KEY
npm run geo:live
# 打开 http://127.0.0.1:3100
npm run geo:test
```

- 多工作区、品牌别名、竞品和无品牌决策问题，持久化至 .geo-data/geo.sqlite（GEO_DB 可覆盖）。
- DeepSeek Chat Completions / Perplexity Agent API；原始响应、明确引用、检索来源分开记录。
- GEO_DAILY_LIMIT 默认 30（UTC，全局，含失败尝试），GEO_PORT 默认 3100。采样可能计费；支持显式启用定时计划及手动重试。
- 仅绑定 127.0.0.1，校验 Host/Origin；单操作员本地使用，**不可直接代理到公网**。不得将 API 样本视为消费者 AI 产品排名。只统计文本提及率及含引用回答比例，不代表推荐率、企业信源引用率或准确率。链接未验证可访问性。
- 后续：权限隔离、业务 UI/API 合并、事实证据与语义推荐分析。

### 阶段 1.2 / 2.1：任务队列与证据分析

- 手动采样进入 SQLite 队列（HTTP 202），单进程每 5 秒领取任务；每日全局额度仍适用。队列最多 200 个未完成任务。
- 定时计划由用户明确启用（60–10080 分钟），默认无计划；每个问题/引擎仅一个有效计划，停机不追赶历史时段。停用会取消尚未执行的计划任务，不中断在途请求。
- 失败、取消、中断均可见。中断请求不自动重放，失败/中断可显式重试（新请求可能计费）。缺少密钥或额度耗尽时暂不领取，服务恢复后继续。
- 近 30 天按问题、供应商、模型分组，提供文本提及率、Wilson 区间、竞品文本命中和明确引用域名（每条回答去重）。至少 10 条有效样本且竞品提及率高 20 个百分点时产生待核查线索，最多关联 5 个样本 ID。阈值为初始启发式，不代表统计显著性或因果关系；Wilson 区间假设独立样本。
- 只运行一个服务实例访问同一个数据库，不可公开部署。自动化依赖本地进程持续运行。尚无语义推荐分类、真实引擎联调或多租户鉴权。

### 阶段 3.1 / 4.1：企业事实证据库与优化行动

- 录入公开/内部证据摘录，保存 URL、时间和内容哈希；仅为人工提交的快照，不自动抓取网页或核验真伪。
- 事实按主体/属性建立版本；草案、批准、驳回及旧版本归档，旧草案不能覆盖更新的已审核版本。仅当前已批准、明确标注公开的证据事实进入可公开提纲。
- 从近 30 天真实监测样本保存去重机会及样本 ID；人工写提纲并关联事实版本。审批及执行记录要求事实版本仍有效。执行后复盘必须关联同一问题、供应商、模型的新有效采样；人工记录结论，不声称因果效果。
- 本地单操作员工作流，审批是显式状态与操作日志，并非多用户独立审批。人工录入的自由文本可能含机密，公开前必须人工审阅；系统不自动发外部内容。自动导入、语义事实核验、跨用户权限和生产部署仍待研发。
- 新增证据/事实/行动 API，继续使用 npm run geo:live 和 npm run geo:test；新表自动创建，保留原 SQLite 数据。

### 阶段 2.2 / 3.2 / 4.2：GEO Agent 辅助分析

- 用户显式确认后，调用已配置模型进行公开证据事实候选提取、成功回答的推荐语境分类与可能冲突分析、基于所选已审核公开事实的优化提纲生成。JSON 结构、原文逐字引文、事实版本 ID 都进行服务端验证。
- `GEO_AGENT_DAILY_LIMIT` 默认 5（UTC，独立于采样额度，包含失败请求）；仅单次人工触发，不自动重试。保留任务状态、输入快照、供应商/模型和校验后的结果。中断不重放。
- 仅公开证据和用户选定的当前批准公开事实进入相关 Agent 输入；回答分析会发送原始问题和回答，确认前请核查是否含敏感信息。模型输出仍不可信，不能自动批准事实或发布内容；逐字引文与事实 ID 验证不证明推理正确。
- 候选可采用为事实草案或待审核行动提纲，采用关系与业务草案同事务写入；过期事实会阻止采用或后续审批。语境分析/冲突仅保留候选，不修改企业事实。仍未提供自动官网抓取、真实供应商端到端联调、多租户鉴权或公网部署。

### 阶段 3.3 / 2.3 / 4.3：公开页面导入、人工复核与效果对比

- `GEO_IMPORT_HOSTS` 由本地管理员设置为逗号分隔的已授权准确主机名，默认空（禁用）。仅 HTTPS、默认端口、无凭据/查询/片段，DNS 检查并固定公网 IPv4 连接，不跟随重定向，限制响应大小及超时。`GEO_IMPORT_DAILY_LIMIT` 默认 10（UTC，含失败）。仅手工指定一页，不递归、不绕过登录或站点限制；操作者须确认授权。HTML 文本提取是简化、可能不完整的快照，最多 3000 Unicode 字符，需人工核验，未运行 JS。TXT/Markdown 本地导入填充证据表单，默认内部，须手工保存。
- Agent 语境结果可人工复核/修正，按样本去重；30 天按采样供应商及模型展示有效数、复核覆盖、已复核推荐比例、当前事实版本的确认冲突样本数与历史版本冲突数。复核样本可能有选择偏差，不外推全量推荐率。
- 已执行优化任务可按执行日志时间比较同问题、供应商及模型的前后 7/14/30 天文本提及率及样本数；不足完整窗口明确标记，不做因果归因。
- 仍是本地单操作者服务；官网实际抓取/真实供应商付费联调、独立多用户身份与生产部署待验证。新增自动化测试使用注入模拟响应。

### 阶段 5.1：真实工作台、登录及角色权限（本地多人版）

- 首次启动必须通过安全终端环境设置 `GEO_ADMIN_USER`（3–100 个字母/数字/._@-）及 `GEO_ADMIN_PASSWORD`（12–128 字符），没有默认账号或密码。首次初始化将已有工作区授予初始管理员；后续启动无需设置密码，也不会重置密码。请备份原 SQLite。例：在终端安全设置变量后执行 `npm run geo:live`，打开 `http://127.0.0.1:3100` 登录。
- 平台管理员创建本地账号；工作区 owner 分配/撤销 owner/editor/reviewer/viewer。普通用户仅可访问其成员工作区，平台管理员不自动拥有其他工作区。任何已登录用户可创建自己的工作区。editor 录入、采样和执行；reviewer 审核/复盘；viewer 只读；owner 全权限。所有成员都可读取本工作区内部资料，未实现资产级权限。最后一个 owner 不得被移除或降级。
- scrypt 密码哈希、随机会话令牌的 SHA-256 存储、8 小时过期、HttpOnly/SameSite Cookie、同源写校验与全局登录频率限制。仅 HTTP loopback；没有密码找回、强制换密、MFA、TLS 或跨实例会话保护。不要直接暴露到公网。后台已授权的定时计划与已排队任务不会因成员移除自动停止，owner 需停用计划。
- 七个真实业务导航与企业设置，指挥舱使用实际样本数/任务数；ROI 页面展示描述性前后对比，尚无真实收入/CRM 归因。原 Next.js 云端演示仍独立。权限由服务端强制执行，部分前端写按钮会显示但提交被拒绝。
- 操作日志保存成功调用的操作者、资源、动作及目标 ID（不保存密码/正文），业务数据与通用日志暂非原子事务；Agent/导入失败也可能记录为已发起操作。HTTP 自动化测试验证登录、同源校验、权限和注销。该版本不是生产级 SaaS。

### 阶段 1.3 / 5.2：更多引擎与本地容器、备份

- 新增 OpenAI Responses API：`OPENAI_API_KEY` + `GEO_OPENAI_MODEL` 为普通模型采样；另设 `GEO_OPENAI_WEB_MODEL` 开启独立 `openai-web` profile，要求完成 web search，分别保存引用与检索来源。两种口径不合并。Gemini GenerateContent：`GEMINI_API_KEY` + `GEO_GEMINI_MODEL`，当前普通文本模式，不启用 Google Search。模型 ID 由管理员按账户实际能力配置，无默认模型、无自动调用。API 采样不代表 ChatGPT/Gemini 消费端；未验证真实付费响应。参考 https://developers.openai.com/api/docs/guides/tools-web-search 与 https://ai.google.dev/api/generate-content 。
- 安全本地 Docker：创建不提交的 `.env.geo`，设置首次管理员、所需供应商密钥与模型；运行 `docker compose -f compose.geo.yml up -d --build`，访问 `http://127.0.0.1:3100`。仅发布宿主机 loopback，容器内部非 root、只读根文件系统、持久卷 `/data`。`GEO_CONTAINER_BIND=1` 仅供该容器模式，不能直接公网部署。初始化后从 env 文件删除管理员初始密码；容器运行时环境仍可能被 Docker 管理员查看。
- 本地数据库备份：`node geo/backup.mjs backup .geo-data/geo.sqlite /secure/path/backup.sqlite`，使用 SQLite VACUUM INTO 生成一致快照（包含 WAL 已提交数据）；备份包含企业敏感信息、密码哈希、会话哈希，需独立加密保管。恢复：`node geo/backup.mjs restore /secure/path/backup.sqlite /secure/path/restored.sqlite`。禁止覆盖已有数据库/sidecar；恢复到新库后撤销会话、停用自动采样计划、取消待采样任务，运行中任务由启动恢复逻辑标记中断。确认后手工停止旧实例并用 GEO_DB 指向新库，不要同时启动两个实例。无远程备份、自动保留、加密或灾备演练服务。
- 健康检查 `/healthz` 不返回业务数据。CI 新增适配器、备份恢复及 Docker 构建/启动检查，不等同于生产上线。

### 阶段 4.4：持久化 Agent 工作流

- owner/editor 可选择一个成功监测样本、已配置非 openai-web Agent 供应商及最多 10 条当前已审核公开事实，明确确认传输及最多两次潜在计费调用后排队。服务每 5 秒推进一步：语境分析候选 → 同问题/供应商/模型机会发现 → 有当前机会、开放任务和公开事实时生成内容候选。不会自动采样、采用候选、审核、执行外部发布或重复运行。
- 独立任务状态和步骤日志，支持排队/步骤间暂停、继续、取消；运行中的暂停会在当前步骤结束后生效，不能撤回已经发出的 API 请求。中断与失败不自动重放；共享现有 Agent 每日额度，额度耗尽时工作流失败。每步检查原始操作者角色与事实版本，撤权后不继续发送。恢复备份取消未完成工作流。
- 当前为单次人工启动的固定流程，并非全天候自主策略、跨平台 Agent 通信或通用 DAG。Agent 输出仍需人工采用与审核。通过注入模拟模型测试，不代表真实付费调用已联调。

### 阶段 4.5：每日策略报告与有限自动编排

- 工作区 owner 显式启用 7/30 天计划（默认关闭），每 UTC 日首次调度生成一个本地策略报告，覆盖近 30 天有效样本、复核、待处理行动、竞品差距及证据 ID；无模型调用。单进程每 30 秒检查，不补跑停机日。报告仅为描述性待办，不是自动确认风险或因果收益。
- 可选 auto 模式仅授权一个指定问题、非联网 Agent provider 与选定公开事实版本，在当天报告生成时选取授权开始后的近 24 小时新成功样本（未运行过工作流或 assess），每工作区每天最多一个工作流、全局 `GEO_AUTO_DAILY_LIMIT` 默认 3（1–20），每流程最多两次潜在计费调用，仍共享 `GEO_AGENT_DAILY_LIMIT`。没有合格样本则当日跳过；不自动采样、重试、采用、审核或发布。未来该问题回答可能含敏感信息，须 owner 确认适合传输；模型配置更改需管理员自行停止计划并重新确认。
- 停止、到期或原授权者失去 owner 角色后，关联自动流程在下一步骤前停止；已发送请求不可撤回。恢复数据库禁用计划并取消未完成流程。报告与自动工作流关联同事务保存，已占用日期不重放。仅本地单实例运行。

### 阶段 4.6 / 5.3：企业内容分发与传播复盘

内容作战新增渠道账号、已批准优化行动关联、独立渠道文案/排期/审核、发布链接及操作档案。仅记录人工真实发布，不执行第三方登录、浏览器自动上传或平台提交。一个行动每渠道一条记录，发布前检查原行动与公开事实版本；取消的任务暂不允许重建同一组合。ROI 页新增人工录入累计数据快照、来源、带时区统计时间、发布后第 1/3/7 个完整 24 小时日龄比较。缺失指标保留 null，不合并跨平台口径或跨币种收入，不声称因果 ROI。货币字段使用最小单位整数。角色权限由服务端执行，编辑者录入、审核者审批、owner 全权限。所有数据本地保存，尚无官方平台 API 自动同步。功能参考来源见 docs/distribution-integration.md。

### 阶段 4.7：内容日历、UTM 与 AI 引用关联

内容作战新增 UTC 月历（独立显示排期与实际发布，不自动发布），每条分发任务可由 owner/editor 确认生成一个稳定的 UTM 落地页链接：source=平台，medium=organic_content，campaign=优化行动 ID，content=分发任务 ID；保留功能参数，拒绝已有 UTM 或敏感凭据链接，不覆盖已登记目的地。操作者须核验公开授权与查询参数不含秘密；链接仅生成，不访问或跳转。UTM 不是自动流量采集。ROI 页面新增发布后最近 7/14/30 日同工作区成功回答的 URL 关联统计，按供应商/模型区分明确引用与检索来源，保留证据样本 ID，去除 UTM 和片段但保留功能查询参数，不合并其他 URL、重定向或跨工作区数据。匹配仅为观察，不表示发布造成引用增长；当前不接入网站分析或 CRM。日历限 1000 条记录、引用证据明细限 100 条，统计覆盖窗口内全部有效样本。原有数据不删除。

### 阶段 4.8：证据驱动的渠道文案 Agent

内容作战中选择已批准行动与已登记渠道，确认后调用非联网 Agent provider 生成一份中文标题/正文候选。11 种渠道使用独立编辑风格与长度目标（不是实时平台技术限制）；仅发送决策问题、品牌、渠道类型及原行动关联的当前已批准公开事实，不发送原提纲、账号名称、内部证据或登录凭据。操作者应核验问题及公开事实适合传输。输出必须含已知事实版本 ID，但不保证事实逻辑蕴含、平台合规或真实发布。共享 GEO_AGENT_DAILY_LIMIT，每次生成最多一个模型请求；失败不重试。候选独立持久化，采用时由操作者指定排期，重新核验行动指纹、事实有效性及渠道唯一约束，原子记录候选采用与分发草稿。审批与实际发布登记仍独立，禁止自动对外发布。不引入第三方品牌或插件。未进行真实付费模型或各平台联调。

### 阶段 2.4：企业官网静态技术诊断

机会洞察新增授权单页诊断及历史对比。复用 GEO_IMPORT_HOSTS 精确白名单、公网 IPv4 DNS 固定连接、HTTPS、无重定向、512 KiB/超时限制；单独 GEO_SITE_AUDIT_DAILY_LIMIT 默认 5（1–50，UTC，含失败），owner/editor 明确确认后执行。读取 HTML 与 X-Robots-Tag，检测标题、描述、语言、H1、简化正文、索引及摘要限制、canonical、JSON-LD 语法与类型、图片 alt。保存内容哈希和证据摘要、整改建议、相同 URL 上次成功诊断状态差异。不执行 JS，不读取 robots.txt 或 sitemap，不验证 Schema.org 语义、真实索引或 AI 排名；静态解析是启发式，不是浏览器 DOM。检测到限制须先确认业务意图，不自动修改网站。测试使用模拟响应，实际官网联调未执行。

### 阶段 2.5：站点诊断、整改与结构化数据

授权同源有限扫描每次最多 10 页、3 个 sitemap、全局每日 3 次；robots.txt 无法读取时停止，匹配禁抓规则保守跳过，不实现完整 RFC 规则或爬虫模拟。只读取白名单公开 HTTPS，静态解析，非无限全站覆盖。整改任务关联原报告及问题；登记整改后需更新的同 URL 单页诊断显示对应信号改善才能复核。结构化数据支持 Organization/WebSite/Article 三种模板，校验字段与 HTTPS URL，不代表完整 Schema.org 语义或富结果资格，不自动写入网站。
